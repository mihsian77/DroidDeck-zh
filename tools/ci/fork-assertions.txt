# fork 关键特性的断言清单，同步上游后自动跑一遍。
#
# 为什么要有这个：白名单是"冲突时整文件保留我们的版本"，上游改动会被丢掉；
# 不在白名单的文件走正常合并，上游删代码也能静默把我们依赖的东西删掉。
# 这两种情况都可能编译通过——只删了 UI 入口或一个字段，Kotlin 照样编过，
# 功能就没了。以前只有 droiddeck-session 的两条字符串检查，覆盖面太窄。
#
# 格式：文件路径|必须出现的字符串|说明
#   - 字符串留空表示只检查文件是否存在
#   - 命中失败只打 warning 并写进 run 摘要，不阻断同步（阻断会挡住正常的版本跟进）
#   - 加新条目时先确认这个字符串是稳定标识，别拿会随文案变的中文句子
#
# 这些断言只覆盖"入口还在不在"，不保证功能逻辑正确；逻辑本身靠单测和真机。
